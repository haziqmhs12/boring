Part 5: Layer 3 Routing with OSPF

Series: Enterprise Multi-Site Campus Network on GNS3. Part 5 of 8.

Only the core and distribution switches run OSPF. Links down to the access layer are passive, so no neighbours form there.

Loopbacks and router IDs

Each Layer 3 device has a loopback /32 from 192.168.0.0/24, and I set the OSPF router ID to that address explicitly. If the router ID is not set, OSPF picks the highest loopback or interface address, and the ID can change when an interface fails.

interface loopback 0
 ip address 192.168.0.2 255.255.255.255
router ospf 1
 router-id 192.168.0.2
 network 192.168.0.2 0.0.0.0 area 0
 network <transit-subnet> 0.0.0.3 area 0
 auto-cost reference-bandwidth 100000
 passive-interface <links towards access layer>

Design decisions

  • Point-to-point transit links use /30 subnets, so no DR election occurs on them.
  • The trunk between the two distribution switches is Layer 2 only, so those two switches do not form an OSPF adjacency with each other. Each one has two Layer 3 uplinks to both cores, which is enough.
  • The port-channel between the cores stays in default broadcast mode, which shows FULL/DR and FULL/BDR and is normal.
  • For routing the reference bandwidth was raised with auto-cost reference-bandwidth 100000.

Verification

Commands I use, in order: show ip interface brief, show ip ospf, show ip ospf neighbor, show ip route.

The server block is joined to the same area: OSPF from HQ to the server distribution pair came up and HSRP works on the server VLAN.
